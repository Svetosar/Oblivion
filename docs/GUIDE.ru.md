# Путеводитель по коду (для тех, кто начинает с Go)

Документ объясняет, **что** лежит в репозитории, **что делает каждый файл и каждая
функция**, **как** через код проходит запрос и **какие приёмы Go** где используются.
Два файла (раздел 6) разобраны построчно. Это образец того, как читать остальные.

Читать удобнее рядом с кодом: пути вида `internal/server/server.go` кликабельны в
редакторе. Номера строк здесь не указаны специально, потому что они меняются с
каждым коммитом. Ищите функцию по имени (в редакторе это Ctrl+F или «Go to symbol»).

> Почему здесь нет буквального описания «каждой строчки». Go-кода в проекте около
> 9 000 строк (с тестами), и построчный пересказ получился бы толще самого кода.
> Кроме того, он устарел бы после первого же коммита. Поэтому сделано так:
> **каждый файл** и **каждая функция** описаны словами (раздел 5), два файла
> разобраны построчно (раздел 6), а сам код снабжён комментариями на английском
> над каждой неочевидной функцией. Если какое-то место непонятно, назовите файл
> и функцию: я распишу его построчно отдельно.

## 1. Что это вообще такое

Проект — это один исполняемый файл (`bin/oblivion`). Внутри него:

- HTTP-сервер (стандартная библиотека Go `net/http`, без фреймворков);
- база SQLite: обычный файл `data/oblivion.db`, отдельный сервер БД не нужен.
  Драйвер `modernc.org/sqlite` написан на чистом Go, без C (правило проекта «No CGO»);
- набор **плагинов**: `auth` (пользователи и вход), `content` (посты, страницы, тема
  сайта, SEO), `media` (картинки);
- собранная админка на React, «зашитая» прямо в бинарник.

Запуск для разработки: `make admin` (собрать админку, нужен Node), затем
`OBLIVION_SECURE_COOKIE=false make run`. Без HTTPS cookie с флагом Secure браузер
не сохранит. Сайт откроется на `http://127.0.0.1:8080/`, админка — на `/admin/`.
При первом запуске в лог пишется `setup_token`: он нужен один раз, чтобы создать
первого администратора. В контейнере его видно через `podman logs <контейнер>`.

Главный принцип — **«всё — плагин»**. Ядро (`internal/`) почти ничего не знает про
посты и пользователей: оно умеет только HTTP, базу, миграции и загрузку плагинов.
Всё остальное делают плагины через публичный API из папки `sdk/`.

## 3. Путь одного запроса

Возьмём `GET /posts/privet-mir` (читатель открывает пост).

1. **Старт программы** (`cmd/oblivion/main.go` → `run`). Программа читает конфиг
   (`config.Load`), открывает БД (`db.Open`), создаёт менеджер плагинов
   (`plugins.New`), регистрирует плагины (`officialplugins.All()`) и запускает
   их (`mgr.Start`). Если не стартовал *обязательный* плагин `auth`, программа
   завершается: это принцип «fail closed» («при сомнении — закрыто»).
2. **Цепочка middleware** (`internal/server/server.go` → `New`). Запрос проходит
   обёртки снаружи внутрь, в таком порядке:
   1. `SecurityHeaders` ставит заголовки CSP, HSTS, X-Frame-Options и т.д. Он
      самый внешний, поэтому заголовки есть даже у ответов 403 и 500.
   2. `Recover` ловит панику (аварию) в обработчике и отвечает 500, а не роняет
      сервер.
   3. `AccessLog` пишет в лог метод, путь, статус и время. IP не пишет
      (приватность).
   4. `Gzip` сжимает текстовые ответы, если браузер это умеет.
   5. `bodyLimit` ограничивает размер тела запроса.
   6. `IdentityMiddleware` выясняет, кто делает запрос.
3. **`IdentityMiddleware`** (`internal/plugins/manager.go`) вызывает сервис
   `identity`, который предоставил плагин `auth`
   (`plugins/auth/session.go` → `Authenticate`). У читателя нет cookie, поэтому он
   анонимен (`nil`). Вошедшему пользователю в контекст запроса кладётся
   `sdk.Principal`: id, имя и права. Если проверка вернула `ErrForbidden`
   (например, неверный CSRF-токен), ответ 403. При любой другой ошибке ответ 500,
   и запрос **никогда** не становится молча анонимным.
4. **Маршрутизатор** (`http.ServeMux`) смотрит на путь: `/healthz` — проверка
   живости, `/admin/...` — админка, `/api/...` — API-маршруты плагинов, всё
   остальное — публичные маршруты плагинов.
5. Плагин `content` при старте зарегистрировал `GET /posts/{slug}`
   (`plugins/content/public.go` → `registerPublic`). Вызывается `handlePost`, а он
   вызывает `showPublished`:
   - SQL-запросом достаёт пост, только если `status = 'published'`;
   - пропускает HTML поста через фильтр `content.html` (`finalHTML`): плагин
     media добавляет картинкам размеры, после чего результат ещё раз очищается
     от опасного HTML;
   - вызывает `render`: тот выбирает язык интерфейса по `Accept-Language`,
     подставляет настройки сайта, строит `<head>` (title, description, OpenGraph,
     JSON-LD) и выполняет HTML-шаблон из `plugins/content/theme/`;
   - `serveBytes` считает ETag (отпечаток страницы). Если у браузера уже есть эта
     версия, он получает короткий ответ `304 Not Modified`.

Запрос в API, например `POST /api/v1/content/items`, проходит тот же путь. Разница
в двух местах. `Authenticate` для изменяющих методов (POST, PUT, PATCH, DELETE)
проверяет CSRF-токен в заголовке `X-CSRF-Token`, а обработчик проверяет права
(`pr.Can("content.write")`).

## 4. Как устроены плагины

Каждый плагин — это тип, у которого есть два метода (интерфейс `sdk.Plugin`,
`sdk/sdk.go`):

```go
Manifest() sdk.Manifest                     // «паспорт»: id, что ему разрешено, его миграции
Init(ctx context.Context, h sdk.Host) error // запуск: тут плагин регистрирует маршруты
```

Плагин может реализовать и третий метод, `Close(ctx) error`, если ему нужно что-то
остановить при выключении. Так делает `auth`: у него есть фоновая очистка сессий.

`Manifest` — это **данные**, а не код. В нём плагин объявляет capabilities:
`db` (база), `kv` (простое хранилище «ключ → значение»), `http.api` (свои
маршруты в `/api/v1/<id>/`), `http.public` (маршруты сайта), `hooks` (хуки),
`storage.files` (личная папка на диске), `identity` (право предоставлять сервис
«кто пользователь»).

`Host` — объект, через который плагин получает доступ к ядру. Если плагин не
объявил право, `Host` вернёт ошибку `ErrCapabilityDenied` (см.
`internal/plugins/host.go`, функция `need`).

> Важно: для **нативных** (вкомпилированных) плагинов это защита от ошибок, а не
> от злого умысла. Go-код внутри процесса может сделать что угодно. Настоящей
> песочницей это станет только для WASM-плагинов, а их отложили на после беты.

Плагины общаются тремя способами:

- **Сервисы** (`Provide`/`Service`): `auth` предоставляет `identity`.
- **Действия** (actions, `DoAction`/`OnAction`). Это событие «что-то случилось»,
  например `auth.login_failed`. Слушатели только узнают о нём.
- **Фильтры** (`ApplyFilters`/`OnFilter`). Значение проходит по цепочке
  слушателей, и каждый может его изменить. Например, `content` отдаёт HTML поста
  в фильтр `content.html`, а `media` добавляет картинкам `width`/`height`. Плагины
  при этом не зависят друг от друга: если media выключен, HTML просто остаётся
  как был.

Испускать хуки плагин может только со своим префиксом (`auth.*` для auth). Слушать
можно только хуки, перечисленные в манифесте.

Таблицы плагина создаются его миграциями: `plugins/<id>/migrations/0001_*.sql`,
`0002_*.sql`… Ядро применяет их при старте по порядку и запоминает, какие уже
применены.

## 5. Каждый файл и каждая функция

Тесты (`*_test.go`) лежат рядом с кодом и здесь не расписаны: каждый тест назван
по тому, что он проверяет (`TestParallelWrongLoginsAreBounded` = «параллельные
неверные входы ограничены»).

### 5.1. `cmd/oblivion/main.go` — точка входа

- `main()` вызывает `run()`. При ошибке печатает её и завершает программу с
  кодом 1: так контейнер и systemd видят, что запуск не удался.
- `run()` — вся последовательность запуска:
  1. `config.Load()` читает переменные окружения;
  2. если передан аргумент `healthcheck`, только проверяет живость и выходит;
  3. настраивает логгер (`slog`, текстом или JSON);
  4. `signal.NotifyContext` создаёт контекст, который отменится по Ctrl+C или
     SIGTERM. Это сигнал «пора выключаться»;
  5. `db.Open` открывает базу;
  6. `plugins.New` создаёт менеджер, `SetDataDir` задаёт папку данных,
     `SetRuntime` передаёт плагинам сведения о среде (Secure-cookie, функция
     «IP клиента»);
  7. регистрирует все плагины и запускает их (`mgr.Start`);
  8. `server.New` собирает сервер, `server.Serve` запускает его до сигнала
     остановки.

  `defer` в этой функции гарантирует обратный порядок закрытия: сначала плагины,
  потом база.
- `healthcheck()` делает запрос к `http://127.0.0.1:<порт>/healthz`. Он нужен
  потому, что в минимальном контейнере (scratch) нет `curl`, и бинарник проверяет
  себя сам.

### 5.2. `internal/brand/brand.go`

Константы с именем продукта: `Slug` (имя файла БД, префикс в логах) и `EnvPrefix`
(`OBLIVION_`). Это единственное место, где записано кодовое имя. Для
переименования проекта достаточно поменять этот файл.

### 5.3. `internal/config/config.go`

- `Config` — структура всех настроек: адрес, папка данных, уровень логов, флаг
  Secure-cookie, лимит тела запроса, время на мягкую остановку, доверенные прокси.
- `DBPath()` — путь к файлу базы.
- `env`, `envDefault`, `envBool` — чтение переменной окружения с префиксом, со
  значением по умолчанию, как true/false.
- `Load()` собирает `Config`. Secure-cookie по умолчанию **включён** (безопасно
  по умолчанию). Неизвестный уровень логов — это ошибка, а не тихое
  игнорирование.
- `parseProxies()` разбирает список IP/подсетей через запятую.

### 5.4. `internal/db/db.go`

- `Open()` создаёт папку данных с правами 0700 и открывает SQLite с настройками:
  - `WAL`: читатели не блокируют писателя;
  - `busy_timeout`: подождать до 5 секунд, если база занята;
  - `foreign_keys`: проверять внешние ключи;
  - `trusted_schema(0)`: защита от вредных схем.

  Кроме того, `Open()` ставит файлу права 0600, ограничивает пул соединений
  четырьмя и применяет миграции ядра.
- `Migrate()` применяет SQL-файлы из папки по порядку номеров. Применённые номера
  записываются в таблицу, и каждая миграция выполняется в транзакции: либо целиком,
  либо никак. Это общий механизм и для ядра, и для плагинов (у каждого своя
  таблица учёта).

### 5.5. `internal/httpx/` — middleware

`middleware.go`:

- `SecurityHeaders` ставит заголовки безопасности:
  - CSP: скрипты и стили только с нашего сайта, встроить сайт во фрейм нельзя;
  - `nosniff`: браузер не угадывает тип файла;
  - `no-referrer`: не сообщать другим сайтам, откуда пришёл читатель;
  - HSTS: «только HTTPS», при Secure-режиме.
- `MaxBody` — простой лимит размера тела.
- `Recover` перехватывает `panic`, пишет её в лог и отвечает 500.
- `statusWriter` — обёртка над ответом, которая запоминает код статуса для лога.
  Её метод `Unwrap` нужен, чтобы `http.ResponseController` мог добраться до
  настоящего соединения: без него не работало продление таймаута при загрузке
  больших файлов.
- `AccessLog` пишет строку лога на каждый запрос.
- `Chain` собирает список middleware в одну цепочку. Первый в списке — самый
  внешний.

`gzip.go`:

- `Gzip` — middleware сжатия.
- `acceptsGzip` / `qValue` разбирают заголовок `Accept-Encoding`. `q=0`, `q=0.0`,
  `q=0.000` означают «не присылай gzip».
- `compressible` решает, стоит ли сжимать этот тип: текст, JSON, XML и SVG — да,
  картинки — нет (они уже сжаты).
- `gzipWriter.decide` принимает решение один раз, перед отправкой заголовков. Не
  сжимает: ответы 204/304/206, уже сжатое, маленькое (меньше 256 байт) и ответы с
  `Cache-Control: no-store`. Последний пункт — защита от атаки BREACH: сжатие
  секрета (CSRF-токена) рядом с текстом, который контролирует атакующий, позволяет
  угадать секрет по размеру ответа.
- `WriteHeader`, `Write`, `Flush`, `Unwrap`, `finish` — обычная обвязка, чтобы
  обёртка вела себя как настоящий ответ. `finish` возвращает компрессор в пул
  (`sync.Pool`), чтобы не выделять память заново на каждый запрос.

`clientip.go`:

- `ClientIPFunc` возвращает функцию «настоящий IP клиента». Заголовку
  `X-Forwarded-For` верим **только** если запрос пришёл от доверенного прокси.
  Иначе любой мог бы написать туда чужой IP и обойти лимит попыток входа.
  Список разбирается справа налево до первого недоверенного адреса.

### 5.6. `internal/plugins/` — менеджер плагинов

`manager.go`:

- `Manager` — состояние: зарегистрированные и активные плагины, маршрутизаторы
  API и сайта, шина хуков, сервисы.
- `New` создаёт менеджер и запоминает, какие плагины обязательные.
- `SetDataDir`, `SetRuntime`, `Register` — настройка до старта.
- `BodyLimit` — лимит тела для пути: плагин media объявил больший лимит для
  загрузки.
- `APIHandler`, `PublicHandler` — два маршрутизатора, которые сервер подключает к
  `/api/` и к `/`.
- `Emit` — испустить хук от имени ядра.
- `Active` — список запущенных плагинов.
- `validate` проверяет манифест: id из латиницы, известные capabilities, версия
  API, имена хуков и прав.
- `Start` — главный метод:
  1. проверяет манифесты;
  2. читает из БД, какие плагины включены (`loadState`);
  3. сортирует их по зависимостям (`order`);
  4. запускает каждый (`startOne`).

  Если упал обязательный плагин, весь старт отменяется.
- `loadState` читает таблицу «включён/выключен».
- `order` выполняет топологическую сортировку: если плагин B требует сервис,
  который предоставляет A, то A запускается раньше. Находит циклы.
- `startOne` применяет миграции плагина, создаёт для него `host` и вызывает
  `Init`. Паника внутри `Init` превращается в ошибку.
- `Close` останавливает плагины в обратном порядке.
- `IdentityMiddleware` описан в разделе 3, шаг 3.

`host.go` — то, что плагин видит как `sdk.Host`:

- `need` — проверка capability. Через неё проходит каждый метод ниже.
- `DB`, `KV`, `Files` выдают доступ к базе, к KV-хранилищу плагина и к его личной
  папке.
- `splitPattern`, `register` разбирают шаблон `"GET /items/{id}"` и регистрируют
  маршрут. Ошибка регистрации (например, конфликт маршрутов) возвращается как
  ошибка, а не как авария.
- `HandleAPI` регистрирует маршрут под `/api/v1/<id-плагина>/`.
- `HandlePublic` регистрирует маршрут сайта, кроме зарезервированных путей
  (`/api/`, `/healthz`, `/admin`).
- `OnAction`, `OnFilter` подписывают плагин на хук, только если хук объявлен в
  манифесте.
- `ownHook`, `DoAction`, `ApplyFilters`: испускать хук можно только со своим
  префиксом.
- `Provide`, `Service` — предоставить сервис и получить сервис другого плагина.

`hooks.go` — шина хуков:

- `onAction`, `onFilter` записывают подписчиков.
- `doAction` вызывает всех подписчиков действия. Паника или ошибка одного
  записывается в лог и не мешает остальным (`safeAction`).
- `applyFilters` пропускает значение через цепочку фильтров. Упавший фильтр
  пропускается, значение идёт дальше без изменений (`safeFilter`).

`kv.go` — KV-хранилище: строки «ключ → байты» в общей таблице, у каждого плагина
своё пространство имён. Методы `Get`, `Set`, `Delete`. Размеры ключа и значения
ограничены.

`files.go` — личная папка плагина:

- `openFiles` открывает `data/plugins/<id>/` через `os.Root`. Это механизм Go,

- `checkName` пропускает только простые имена без `/`.
- `Create`, `Open`, `Remove` — создать, открыть и удалить файл.

### 5.7. `internal/server/server.go`

### 5.8. `internal/admin/admin.go`

- `distFS` — собранная админка (`admin/dist`), вшитая через `//go:embed`.

### 5.11. `plugins/auth/` — пользователи и вход

`plugin.go`:

- `Plugin` — состояние плагина: база, два лимитера, счётчик одновременных
  проверок паролей, setup-токен.
- `New` создаёт лимитеры:
  - на сеть: 10 бесплатных ошибок, затем блокировка от 30 секунд до 15 минут;
  - на имя пользователя: 20 ошибок, затем мягкое замедление от 1 секунды до
    2 минут.
- `Manifest` объявляет права (`db`, `http.api`, `hooks`, `identity`).
- `Init` получает базу, предоставляет сервис `identity`, регистрирует маршруты,
  при необходимости выпускает setup-токен и запускает очистку сессий.
- `maybeIssueSetupToken` выпускает токен, только если в базе 0 пользователей.
- `emit` испускает хук `auth.*`.
- `principalOf` — короткий способ достать Principal из запроса.
- `startCleanup` при старте и затем раз в час удаляет просроченные сессии.
- `Close` останавливает очистку.

`roles.go`:

- `rolePerms` — три фиксированные роли: `admin` (всё), `editor` (все посты и
  медиа), `author` (только свои посты).
- `validRole`, `principalFor` — проверка роли и сборка Principal из роли.

`password.go`:

- Константы argon2id: 19 МиБ памяти, 2 прохода. Это рекомендация OWASP.
- `acquireHash` — очередь на хеширование. Одновременно идут не больше 2
  проверок, ещё 8 могут ждать, остальным сразу отвечается 503 («сервер
  занят»). Хеш пароля намеренно тяжёлый, и без очереди 100 одновременных входов
  съели бы всю память.
- `hashPassword` — соль + argon2id. Результат записывается строкой формата PHC
  (`$argon2id$v=19$m=...`).
- `verifyPassword` разбирает строку, **проверяет границы параметров**
  (память ≤ 64 МиБ, длина ключа 16–64 байта: подделанная строка в БД не должна
  съесть всю память) и сравнивает за постоянное время (`subtle.ConstantTimeCompare`),
  чтобы время ответа не выдавало, сколько байт совпало.
- `validatePassword` проверяет минимальную и максимальную длину пароля.

`limiter.go` — ограничитель попыток:

- `limiter` хранит таблицу «ключ → число ошибок, время последней, блокировка до».
  Размер таблицы жёстко ограничен (10 000 записей).
- `check` отвечает, сколько ещё ждать по этому ключу.
- `fail` / `failLocked` засчитывают ошибку. После `free` ошибок включается
  блокировка, которая удваивается с каждой следующей ошибкой (`base << n`), но не
  больше `cap`.
- `reserve` **атомарно** проверяет ключ и заранее засчитывает попытку как
  ошибку. Зачем: если 100 запросов придут одновременно, все они прошли бы
  `check` раньше, чем первый успел бы записать `fail`. С `reserve` пропускается
  ровно 11, это проверено тестом.
- `refund` возвращает резерв, если попытка не оказалась ошибкой. Прошлые ошибки
  при этом не стираются.
- `reset` удаляет ключ полностью: после успешного входа счётчик имени
  пользователя обнуляется.
- `evict` освобождает место при переполнении: сначала удаляет старые записи,
  затем 10% самых давних.
- `limitKey` превращает IP в ключ. IPv6 группируется по /64, потому что у
  одного абонента обычно целая /64, и иначе он мог бы менять адрес на каждой
  попытке.

`attempt.go` разобран построчно в разделе 6.2.

`session.go` — сессии и CSRF:

- `cookieName` возвращает `__Host-sid` при HTTPS (браузер тогда гарантирует, что
  cookie нельзя подменить с поддомена) или `sid`.
- `setCookie` ставит cookie: `HttpOnly` (JS её не видит), `SameSite=Strict`,
  `Secure`.
- `hashToken` — SHA-256 от токена. **В базе хранится только хеш**, поэтому утечка
  базы не даёт войти в чужие сессии.
- `randToken` — криптографически случайный токен.
- `newSession` создаёт сессию с CSRF-токеном. Если у пользователя больше 10
  сессий, удаляются самые старые.
- `cleanupSessions` удаляет просроченные сессии.
- `lookup` находит сессию по cookie и проверяет, что она не истекла, а
  пользователь не отключён.
- `isSafeMethod` — GET, HEAD и OPTIONS ничего не меняют, поэтому CSRF для них не
  проверяется.
- `csrfExempt` — исключения: вход и первичная настройка (до них сессии ещё нет).
- `Authenticate` — сервис `identity`: найти сессию; для изменяющих запросов
  проверить CSRF.
- `checkCSRF` сверяет токен в заголовке за постоянное время, затем вызывает
  `checkOrigin`.
- `checkOrigin` отвергает запрос, если браузер сообщил, что он пришёл с другого
  сайта (`Sec-Fetch-Site`, `Origin`).
- `revokeSessions` удаляет все сессии пользователя (кроме текущей). Вызывается
  при смене пароля.

`handlers.go` — HTTP-обработчики:

- `registerRoutes` — таблица маршрутов `/api/v1/auth/...`.
- `internalErr` пишет ошибку в лог и отвечает «internal error». Подробности
  клиенту не показываются.
- `hashErr` выбирает ответ при сбое хеширования: 503 «занято»; ничего, если
  клиент ушёл; 500 в остальных случаях.
- `decode` читает JSON (лимит 1 МиБ).
- `tooMany` отвечает 429 с заголовком `Retry-After`.
- `clientIP`, `ipKey`, `userKey` формируют ключи для лимитеров. Имя приводится к
  нижнему регистру и обрезается до 64 символов, чтобы нельзя было раздуть память
  длинными именами.
- `startSession` создаёт сессию и ставит cookie.
- `findUser` ищет пользователя по имени без учёта регистра.
- `issueSetupToken` выпускает одноразовый токен на 1 час и пишет его в лог.
- `handleSetupStatus` сообщает админке, нужна ли первичная настройка.
- `handleSetup` создаёт первого администратора. Сверяет токен; SQL `INSERT ...
  WHERE NOT EXISTS` гарантирует, что два одновременных запроса не создадут двух
  админов.
- `handleLogin` — вход:
  1. резервирует попытку (`begin`);
  2. ищет пользователя;
  3. **всегда** проверяет пароль: для несуществующего пользователя —
     против «пустышки» `dummyHash`, чтобы по времени ответа нельзя было узнать,
     есть ли такой пользователь;
  4. при ошибке засчитывает её, при успехе создаёт сессию.
- `handleLogout` удаляет сессию и cookie.
- `handleMe` отвечает, кто я, и выдаёт CSRF-токен.
- `handlePassword` — смена пароля: проверяет текущий (тоже через лимитер),
  сохраняет новый хеш и разлогинивает все остальные устройства.
- `requireManage` проверяет право управлять пользователями.
- `handleListUsers`, `handleCreateUser`, `handleUpdateUser`, `handleDeleteUser` —
  управление пользователями. Важная деталь: нельзя удалить, отключить или
  понизить **последнего** активного администратора. Проверка делается внутри
  того же SQL-запроса, без окна для гонки.
- `userID` разбирает `{id}` из пути.

### 5.12. `plugins/content/` — посты, страницы, сайт

`plugin.go`:

- `Plugin` — состояние плагина: база, KV, настройки, `version` (счётчик
  изменений) и `docs` (кэш sitemap и RSS).
- `Manifest` / `Init` — права и запуск. `Init` также вызывает `backfillDerived`.
- `backfillDerived` заполняет для старых записей вычисляемые поля (`lead`,
  `og_image`), если миграция 0002 добавила их пустыми. Работает пачками по 100.

`render.go`:

- `md` — конвертер Markdown (goldmark + GFM: таблицы, зачёркивание). **Сырой HTML
  в Markdown выключен**.
- `policy` — правила очистки HTML (bluemonday, политика UGC); ссылки получают
  `rel="nofollow noreferrer"`.
- `filteredPolicy` — те же правила плюс `loading`/`decoding` у картинок. Ими
  очищается результат фильтров.
- `renderMarkdown` переводит Markdown в HTML и очищает результат.
- `headingShift` понижает заголовки на уровень: `#` становится `<h2>`, потому что
  `<h1>` на странице один — это название поста.

`api.go` — API админки (`/api/v1/content/...`):

- `itemView` — так пост выглядит в JSON.
- `registerAPI` — таблица маршрутов.
- `principal` требует, чтобы пользователь вошёл (иначе 401).
- `canWrite` — может ли пользователь править этот пост (автор правит только свои).
- `scanItem` читает строку из БД в `itemView`; `extra` — дополнительные колонки.
- `itemID`, `load` — разбор id и загрузка поста.
- `handleList` — список с фильтрами и постраничностью. Автор видит только своё.
- `handleGet` — один пост.
- `itemIn.validate` проверяет вид, заголовок, slug, статус и размер.
- `reservedSlug`: страницы не могут занять служебные адреса (`feed.xml`,
  `sitemap.xml`…).
- `handleCreate` — создание:
  1. Markdown → HTML;
  2. `derive` считает анонс и картинку для соцсетей;
  3. `INSERT`. Если slug не задан, он генерируется из заголовка, а при занятом
     пробуются `-2`, `-3`…;
  4. `version` увеличивается, и это сбрасывает кэш sitemap/RSS.
- `handleUpdate` — то же для правки. Дата первой публикации сохраняется.
- `handleDelete` — удаление (опубликованное удаляет только тот, у кого есть право
  публиковать).
- `handlePreview` — предпросмотр Markdown для редактора, ровно как при
  публикации.

`public.go` — сайт:

- `navItem`, `listEntry`, `pageData` — данные для шаблонов.
- `funcs` — функции шаблонов (`date`).
- `page` собирает шаблон из `layout.html` и файла страницы.
- `registerPublic` регистрирует маршруты сайта: `/`, `/posts/{slug}`, `/{slug}`,
  `/theme/...`, `robots.txt`, `sitemap.xml`, `feed.xml`.
- `redirectNoSlash` переадресует 301 со слэша в конце на адрес без него, чтобы
  у одной страницы не было двух адресов.
- `handleFavicon`, `handleCSS` отдают иконку и стили темы.
- `render` — общая часть всех страниц: язык, настройки сайта, `<head>`, меню,
  ETag.
- `structuredData` — JSON-LD (разметка для поисковиков: «это статья, вот дата,
  вот автор»).
- `notFound` — красивая страница 404.
- `nav` — меню из опубликованных страниц.
- `handleIndex` — главная: 10 постов на странице, `?page=N`; страница за
  пределами списка отдаёт 404.
- `showPublished`, `handlePost`, `handlePage` — пост или страница (раздел 3).

`seo.go` — SEO и документы:

- `plainText` — HTML → чистый текст. В конце блоков ставится пробел, чтобы слова
  из соседних абзацев не слиплись.
- `leadText` — текст первых абзацев (до 600 символов). Заголовки и списки
  пропускаются, если есть обычные абзацы.
- `derive` считает анонс и картинку при **сохранении**, а не при каждом
  просмотре (это ускорение).
- `excerpt` обрезает текст до N символов по границе слова и ставит «…».
- `ogImage` — первая загруженная картинка поста (для превью в соцсетях).
- `head`, `openGraph`, `ldScript`, `isoDate` — содержимое `<head>`. `json.Marshal`
  экранирует `<`, поэтому JSON-LD не может «закрыть» тег `<script>`.
- `handleRobots` — `robots.txt`.
- `handleSitemap` — `sitemap.xml`, список адресов для поисковиков.
- `handleFeed` — RSS: 20 последних постов.
- `absolutize` превращает ссылки `/x` в `https://сайт/x` для RSS-читалок.
- `docCache` / `cachedDoc` — кэш sitemap и RSS. Документ строится один раз и
  отдаётся из памяти, пока не изменится `version`, а она меняется при любом
  сохранении поста или настроек.
- `serveBytes` отправляет ответ с ETag и умеет отвечать 304.
- `etagMatches` сравнивает ETag из запроса.
- `finalHTML` пропускает HTML поста через фильтр `content.html`. Если фильтр
  что-то изменил, результат **очищается заново**: чужому плагину не доверяем.

`settings.go` — настройки сайта:

- `settings` — название, описание, базовый адрес (`base_url`) и язык постов.
- `normalize` очищает и проверяет значения. Например, `base_url` должен быть
  `https://домен` без пути и без логина/пароля.
- `settingsStore` — копия настроек в памяти.
- `settings()` берёт настройки из памяти, а при первом обращении — из KV под
  блокировкой.
- `handleGetSettings`, `handlePutSettings` — API. Менять может только
  администратор. Запись в базу и обновление копии в памяти идут под **одной**
  блокировкой, чтобы два одновременных сохранения не разошлись.

`i18n.go` — язык интерфейса сайта:

- `tr` — строки интерфейса («Новее», «Старше», «Страница не найдена»…).
- `langRU`, `langEN` — два набора строк.
- `pickLang` выбирает язык по заголовку `Accept-Language` с учётом `q`. По
  умолчанию русский. **Посты не переводятся**: переводятся только надписи
  интерфейса.

`slug.go`:

- `slugRe` — допустимый slug: `a-z`, `0-9` и дефисы.
- `reservedPageSlugs` — занятые служебные имена.
- `translit` + `slugify` делают slug из заголовка с транслитерацией кириллицы:
  «Привет мир» → `privet-mir`.

`theme/` — шаблоны сайта:

- `layout.html` — общий каркас: `<head>`, шапка, меню, `<main>`. Атрибут
  `<html lang>` равен языку постов. Если язык интерфейса другой, элементы
  интерфейса получают свой `lang` (через `UIAttr`), и экранный диктор читает
  каждую часть с правильным произношением.
- `index.html` — главная, `single.html` — пост или страница, `notfound.html` — 404.
- `style.css`, `favicon.svg` — стили и иконка.
- В шаблонах `{{.Поле}}` означает «вставить значение». `html/template` сам
  экранирует данные, поэтому подставить скрипт через заголовок поста нельзя.

`migrations/` — `0001_init.sql` создаёт таблицу `content_items`; `0002_derived.sql`
добавляет колонки `lead`, `og_image`, `derived`.

### 5.13. `plugins/media/` — картинки

`plugin.go`:

- Константы: картинка до 10 МиБ, до 50 мегапикселей, квота 200 МиБ на одного
  загружающего, 3 минуты на загрузку.
- `Plugin`, `New`, `Manifest`, `Init` — регистрирует API, раздачу `/media/{name}` и
  фильтр `content.html`.

`api.go`:

- `itemView`, `cols`, `scan` — картинка в JSON и чтение из БД.
- `need` проверяет вход и право.
- `cleanFilename` очищает исходное имя файла (оно только для показа, на диск
  файл ложится под случайным именем).
- `handleUpload` — загрузка:
  1. продлевает таймаут чтения для этого запроса;
  2. читает файл с лимитом;
  3. `sniff` определяет тип **по байтам**, а не по расширению;
  4. `strip` вырезает метаданные;
  5. проверяет размеры по заголовку картинки (до декодирования пикселей, защита
     от «пиксельной бомбы»);
  6. проверяет квоту;
  7. записывает файл под случайным именем и строку в БД.
- `handleList` — список, `handleDelete` — удаление (чужие удаляет только тот, у
  кого есть `media.manage`).
- `handleServe` отдаёт файл, только если имя строго вида `<32 hex>.<ext>`.

`strip.go` — удаление метаданных (EXIF, GPS, комментарии) без перекодирования
картинки:

- `sniff` — сигнатуры JPEG, PNG, GIF и WebP.
- `strip` выбирает нужную функцию.
- `stripJPEG` проходит по сегментам и оставляет только нужные для изображения.
  Останавливается на **первом** маркере конца изображения: к файлу можно
  «приклеить» второй JPEG с GPS. Поворот (`orientation`) сохраняется отдельным
  чистым сегментом (`exifOrientation`, `orientationSegment`), иначе фото с
  телефона легли бы набок.
- `stripPNG` оставляет только разрешённые блоки (`pngKeep`).
- `stripGIF` и `stripWEBP` делают то же для своих форматов.

`filter.go`:

- `filterHTML` — подписчик фильтра `content.html`. Находит `<img>` наших картинок
  и добавляет `width`/`height` (страница не «прыгает» при загрузке),
  `loading="lazy"` и `decoding="async"`.
- `dimensions` берёт размеры из кэша или из БД. Неизвестные имена запоминаются на
  минуту (отрицательный кэш), чтобы пост с битой ссылкой не дёргал базу на каждом
  просмотре. Кэш ограничен 2000 записями.

`util.go` — `bytesReader`, мелкий помощник.

### 6.1. `cmd/oblivion/main.go`, функция `run`

```go
func run() error {                       // возвращает ошибку; nil = всё хорошо
	cfg, err := config.Load()            // прочитать OBLIVION_* ; := объявляет переменные
	if err != nil {                      // в Go ошибки проверяются явно после каждого шага
		return err                       // и передаются наверх, в main
	}
	if len(os.Args) > 1 {                // есть аргумент командной строки?
		switch os.Args[1] {
		case "healthcheck":
			return healthcheck(cfg)      // режим «проверить живость и выйти»
		default:
			return fmt.Errorf("unknown command %q", os.Args[1]) // %q = значение в кавычках
		}
	}
	var lvl slog.Level                   // уровень логов: debug/info/warn/error
	_ = lvl.UnmarshalText([]byte(cfg.LogLevel)) // "_ =" — ошибку игнорируем: уровень уже проверен в config
	opts := &slog.HandlerOptions{Level: lvl} // & — взять указатель на новую структуру
	var h slog.Handler = slog.NewTextHandler(os.Stderr, opts) // логи текстом в stderr
	if cfg.LogJSON {
		h = slog.NewJSONHandler(os.Stderr, opts) // или в JSON (удобно в контейнере)
	}
	log := slog.New(h)

	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()                         // ctx «отменится» по Ctrl+C / SIGTERM; defer = выполнить при выходе

	d, err := db.Open(ctx, cfg.DBPath()) // открыть SQLite и применить миграции ядра
	if err != nil {
		return err
	}
	defer d.Close()                      // закрыть базу последней (defer'ы идут в обратном порядке)

	mgr := plugins.New(log, d, officialplugins.EssentialIDs...) // ... = развернуть срез в аргументы
	mgr.SetDataDir(cfg.DataDir)
	mgr.SetRuntime(sdk.Runtime{SecureCookies: cfg.SecureCookie, ClientIP: httpx.ClientIPFunc(cfg.TrustedProxies)})
	for _, p := range officialplugins.All() { // range = цикл по списку; _ = индекс не нужен
		mgr.Register(p)
	}
	if err := mgr.Start(ctx); err != nil { // упал обязательный плагин → выходим (fail closed)
		return err
	}
	defer mgr.Close(context.Background()) // остановить плагины перед закрытием базы

	srv := server.New(cfg, log, d, mgr)  // собрать http.Server
	return server.Serve(ctx, srv, cfg.ShutdownWait, log) // работать до сигнала, потом мягко остановиться
}
```

### 6.2. `plugins/auth/attempt.go` — одна попытка ввода пароля

Задача файла: каждая проверка пароля (вход, смена пароля) должна пройти через
лимитеры **до** тяжёлого хеширования, а одна сеть не должна занимать больше одного
«слота» хеширования одновременно.

```go
const perNetHashes = 1
// Сколько проверок пароля одновременно разрешено одной сети. Глобально слотов 2,
// поэтому 1 на сеть: один клиент не может занять все слоты и заблокировать остальных.

type flights struct {        // «сколько проверок сейчас в полёте» по каждой сети
	mu sync.Mutex            // мьютекс: к карте обращаются много горутин сразу
	n  map[string]int        // ключ сети → число идущих проверок
}

func (f *flights) enter(key string) bool { // попытаться занять слот
	f.mu.Lock()              // заблокировать: дальше мы одни
	defer f.mu.Unlock()      // разблокировать при выходе из функции (в любом случае)
	if f.n == nil {
		f.n = map[string]int{} // карта создаётся лениво, при первом обращении
	}
	if f.n[key] >= perNetHashes {
		return false         // у этой сети уже идёт проверка → отказ
	}
	f.n[key]++               // занять слот
	return true
}

func (f *flights) leave(key string) { // освободить слот
	f.mu.Lock()
	defer f.mu.Unlock()
	if f.n[key]--; f.n[key] <= 0 { // уменьшить; если стало 0 —
		delete(f.n, key)     // удалить ключ, чтобы карта не росла бесконечно
	}
}

type attempt struct {        // одна попытка
	p      *Plugin           // ссылка на плагин (там лимитеры)
	ik, uk string            // ключ сети и ключ имени пользователя
	state  int               // 0 = прервана, 1 = неудача, 2 = успех
}

func (p *Plugin) begin(w http.ResponseWriter, ik, uk string) *attempt {
	if d := p.ipLimit.reserve(ik); d > 0 { // зарезервировать попытку для сети
		tooMany(w, d)        // сеть заблокирована → 429 «подождите d»
		return nil           // nil = «попытки не будет», вызывающий просто выходит
	}
	if d := p.userLimit.reserve(uk); d > 0 { // то же для имени пользователя
		p.ipLimit.refund(ik) // вернуть уже взятый резерв сети: попытки не было
		tooMany(w, d)
		return nil
	}
	if !p.inflight.enter(ik) { // от этой сети уже идёт проверка?
		p.ipLimit.refund(ik) // вернуть оба резерва
		p.userLimit.refund(uk)
		w.Header().Set("Retry-After", "1")
		writeErr(w, http.StatusTooManyRequests, "another sign-in from this network is still being checked")
		return nil
	}
	return &attempt{p: p, ik: ik, uk: uk} // всё ок: попытка разрешена, state = 0
}

func (a *attempt) failed()    { a.state = 1 } // обработчик: «пароль неверный»
func (a *attempt) succeeded() { a.state = 2 } // обработчик: «пароль верный»

func (a *attempt) finish() { // вызывается через defer в конце обработчика
	a.p.inflight.leave(a.ik) // освободить слот сети
	switch a.state {
	case 0:                  // прервана (сервер занят, клиент ушёл, ошибка БД):
		a.p.ipLimit.refund(a.ik) // это не ошибка пользователя → вернуть оба резерва
		a.p.userLimit.refund(a.uk)
	case 2:                  // успех:
		a.p.ipLimit.refund(a.ik) // вернуть резерв сети, но прошлые ошибки сети НЕ прощать
		a.p.userLimit.reset(a.uk) // счётчик имени — обнулить
	}                        // case 1 (неудача): резерв остаётся засчитанной ошибкой
}
```

Как это используется в `handleLogin`:

```go
att := p.begin(w, ik, uk) // зарезервировать
if att == nil {
	return                // 429 уже отправлен
}
defer att.finish()        // что бы ни случилось дальше — итог будет подведён
// ... проверка пароля ...
att.failed()  или  att.succeeded()
```

Почему по умолчанию «прервана» (state = 0): если в обработчике случится
неожиданный `return` (ошибка БД, перегрузка), попытка не засчитается
пользователю как ошибка. Ошибкой считается только то, что явно отмечено
`failed()`.

## 7. Приёмы Go, которые встречаются в коде

| Приём | Как выглядит | Где посмотреть |
|---|---|---|
| **Пакет** = папка; имя с заглавной буквы = публичное | `func New()` видна снаружи, `func handler()` — нет | везде |
| **`internal/`** | Импортировать можно только изнутри этого модуля | `internal/*` |
| **Ошибки — это значения** | `if err != nil { return err }` вместо исключений | везде |
| Обёртка ошибок | `fmt.Errorf("...: %w", err)`, проверка `errors.Is(err, sdk.ErrForbidden)` | `plugins/auth/session.go`, `manager.go` |
| **Интерфейс** — набор методов; тип реализует его «молча» | `sdk.Plugin`, `sdk.Host`, `sdk.Identity` | `sdk/sdk.go` |
| Структура + методы | `func (p *Plugin) handleLogin(w, r)`: метод с «получателем» `p` | `plugins/auth/handlers.go` |
| **`http.Handler`** | Всё, у чего есть `ServeHTTP(w, r)`. `http.HandlerFunc` превращает функцию в Handler | `internal/httpx/middleware.go` |
| **Middleware** | Функция `func(next http.Handler) http.Handler`, оборачивает следующий обработчик | `httpx.Chain`, `server.go` |
| Маршруты Go 1.22+ | `"GET /items/{id}"`, затем `r.PathValue("id")` | `plugins/content/api.go` |
| **`context.Context`** | Несёт отмену запроса и «принципала»; `sdk.PrincipalFrom(r.Context())` | `sdk/sdk.go` (внизу) |
| `database/sql` | `QueryRowContext(...).Scan(&a, &b)`, `ExecContext`; `?` — плейсхолдеры (защита от SQL-инъекций) | любой плагин |
| Транзакция | `tx, _ := db.BeginTx(...)`, `defer tx.Rollback()`, `tx.Commit()` | `handleUpdateUser` в auth |
| **`defer`** | Выполнится при выходе из функции (закрыть файл, отпустить мьютекс) | везде |
| **`//go:embed`** | Вшивает файлы в бинарник при компиляции | `content/public.go` (тема), `internal/admin/admin.go` |
| Мьютекс | `sync.Mutex` / `RWMutex` защищает общие данные между горутинами | `auth/limiter.go`, `content/settings.go` |
| Атомарный счётчик | `atomic.Int64`: `Add(1)`, `Load()` без мьютекса | `content/plugin.go` (`version`) |
| Канал как семафор | `make(chan struct{}, 2)`: не больше двух одновременно | `auth/password.go`, `media/plugin.go` |
| Пул объектов | `sync.Pool`: переиспользовать дорогие объекты | `httpx/gzip.go` |
| Замыкание | `func() ([]byte, error) { ... }` видит переменные снаружи | `cachedDoc` в `content/seo.go` |
| Вариативные аргументы | `func scanItem(s scanner, extra ...any)` | `content/api.go` |
| Указатель для «необязательного поля» | `*string` в JSON: `nil` = поле не прислали | `handleUpdateUser` |
| `html/template` | Автоматически экранирует данные; `template.HTML` = «доверяю, не экранировать» | `content/public.go` |
| **Тесты** | Файлы `*_test.go`, функции `TestXxx(t *testing.T)`, `httptest` — фальшивые запросы | все `*_test.go` |

Команды: `go test ./...` (тесты), `go vet ./...` (статический анализ),
`gofmt -w .` (форматирование: в Go стиль не обсуждается, его задаёт инструмент).
`make check` = vet + тесты с детектором гонок (`-race`).

## 11. Словарь

- **Handler**: функция или объект, который отвечает на HTTP-запрос.
- **Middleware**: обёртка вокруг handler, которая что-то делает до или после него.
- **Principal**: «кто делает запрос» (пользователь и его права).
- **Capability**: право плагина пользоваться частью ядра.
- **Хук**: точка расширения. Action — «сообщить о событии», filter — «дать изменить
  значение».
- **Миграция**: SQL-файл, который приводит схему БД к нужной версии.
- **Slug**: часть URL, например `privet-mir` в `/posts/privet-mir`.
- **CSRF**: атака, когда чужой сайт заставляет браузер вошедшего пользователя
  отправить запрос к нам.
- **CSP**: заголовок, который запрещает браузеру выполнять чужие и inline-скрипты.
- **XSS**: внедрение чужого скрипта в страницу.
- **ETag / 304**: отпечаток версии страницы. Если у браузера та же версия, сервер
  отвечает коротко: «не изменилась».
- **Горутина**: лёгкий поток Go; каждый HTTP-запрос обрабатывается в своей.
- **Гонка (race)**: две горутины одновременно меняют одни данные. Ищется
  `go test -race`.
- **embed**: вшивание файлов в бинарник.
