# Путеводитель по коду (для тех, кто начинает с Go)

Документ объясняет, **что** лежит в репозитории, **как** через код проходит запрос
и **какие приёмы Go** где используются. Читать удобнее рядом с кодом: пути
вида `internal/server/server.go` кликабельны в редакторе.

---

## 1. Что это вообще такое

Проект — это один исполняемый файл (`bin/oblivion`). Внутри него:

- HTTP-сервер;
- база SQLite (обычный файл `data/oblivion.db`, отдельный сервер БД не нужен);
- набор **плагинов**: `auth` (пользователи и вход), `content` (посты и страницы),
  `media` (картинки);
- собранная админка на React, «зашитая» прямо в бинарник.

Запуск: `make admin` (собрать админку, нужен Node) → `make run`. Сайт откроется на
`http://127.0.0.1:8080/`, админка — на `/admin/`. При первом запуске в лог пишется
`setup_token`: он нужен, чтобы создать первого администратора.

Главный принцип — **«всё — плагин»**. Ядро (`internal/`) почти ничего не знает про
посты и пользователей: оно умеет только HTTP, базу, миграции и загрузку плагинов.
Всё остальное делают плагины через публичный API из папки `sdk/`.

## 2. Карта папок

```
cmd/oblivion/main.go     точка входа: читает конфиг, открывает БД, запускает плагины и сервер
internal/                ЯДРО. Go запрещает импортировать internal/ извне модуля
  brand/                 имя продукта в одном месте ("oblivion" — только кодовое имя)
  config/                настройки из переменных окружения OBLIVION_*
  db/                    открытие SQLite + система миграций (SQL-файлы по номерам)
  httpx/                 middleware: заголовки безопасности, логи, лимиты, IP клиента
  plugins/               менеджер плагинов: проверка манифестов, порядок запуска,
                         «хост» с проверкой прав (capabilities), шина хуков, KV, файлы
  server/                собирает всё в один http.Server
  admin/                 отдаёт собранную React-админку по адресу /admin/
sdk/                     ПУБЛИЧНЫЙ API для плагинов (единственное, что плагинам можно импортировать)
plugins/                 официальные плагины
  plugins.go             список плагинов, которые вкомпилированы в бинарник
  boundary_test.go       тест: плагины не лезут во внутренности ядра
  auth/                  пароли, сессии, CSRF, роли, лимит попыток входа
  content/               посты/страницы в Markdown, API, встроенная тема сайта
  media/                 загрузка картинок, удаление метаданных (EXIF и т.п.)
admin/                   исходники админки (React + TypeScript + Vite)
deploy/Containerfile     сборка контейнерного образа (Podman/Docker)
Makefile                 команды: make check / build / admin / run / image
```

## 3. Путь одного запроса

Возьмём `GET /posts/privet-mir` (читатель открывает пост).

1. **`cmd/oblivion/main.go` → `run()`**: при старте программа уже прочитала конфиг
   (`config.Load`), открыла БД (`db.Open`), создала менеджер плагинов
   (`plugins.New`), зарегистрировала плагины (`officialplugins.All()`) и запустила
   их (`mgr.Start`). Если не стартовал *обязательный* плагин `auth`, программа
   завершается: принцип «fail closed».
2. **`internal/server/server.go` → `New`** построил цепочку middleware. Запрос
   проходит её снаружи внутрь:
   `Recover` (ловит панику) → `AccessLog` (пишет метод, путь, статус; IP не пишет)
   → `IdentityMiddleware` (кто это?) → `SecurityHeaders` (CSP и др.) → `bodyLimit`
   (ограничение размера тела запроса).
3. **`IdentityMiddleware`** (`internal/plugins/manager.go`) вызывает сервис
   `identity`, который предоставил плагин `auth`
   (`plugins/auth/session.go` → `Authenticate`). У читателя нет cookie, поэтому он
   анонимен (`nil`). У вошедшего пользователя в контекст запроса кладётся
   `sdk.Principal`: id, имя и права.
4. **Маршрутизатор** (`http.ServeMux`) смотрит на путь. `/api/...` уходит в
   API-маршруты плагинов, `/admin/...` — в админку, всё остальное — в публичные
   маршруты плагинов.
5. Плагин `content` при старте зарегистрировал `GET /posts/{slug}`
   (`plugins/content/public.go`). Вызывается `handlePost`: он достаёт `slug` через
   `r.PathValue("slug")`, делает SQL-запрос и рендерит HTML-шаблон из
   `plugins/content/theme/`.

Запрос в API, например `POST /api/v1/content/items`, идёт так же. Разница в том, что
`Authenticate` для изменяющих методов (POST, PUT, PATCH, DELETE) проверяет
CSRF-токен в заголовке `X-CSRF-Token`, а обработчик проверяет права
(`pr.Can("content.write")`).

## 4. Как устроены плагины

Каждый плагин — это тип, у которого есть два метода (интерфейс `sdk.Plugin`,
`sdk/sdk.go`):

```go
Manifest() sdk.Manifest                     // «паспорт»: id, что ему разрешено, его миграции
Init(ctx context.Context, h sdk.Host) error // запуск: тут плагин регистрирует маршруты
```

`Manifest` — это **данные**, а не код. В нём плагин объявляет capabilities:
`db` (база), `http.api` (свои маршруты в `/api/v1/<id>/`), `http.public`
(маршруты сайта), `storage.files` (личная папка на диске) и т.д. `Host` — объект,
через который плагин получает доступ к ядру. Если плагин не объявил право, `Host`
вернёт ошибку `ErrCapabilityDenied` (см. `internal/plugins/host.go`, функция
`need`).

> Важно: для **нативных** (вкомпилированных) плагинов это защита от ошибок, а не
> от злого умысла. Go-код внутри процесса может сделать что угодно. Настоящей
> песочницей это станет только для WASM-плагинов, а их отложили на после беты.

Плагины общаются через **сервисы** (`Provide`/`Service`): `auth` предоставляет
`identity`. И через **хуки**: `auth` испускает `auth.login_failed` и т.п., а
будущий плагин аудита сможет их слушать.

Таблицы плагина создаются его миграциями: `plugins/<id>/migrations/0001_*.sql`.
Ядро применяет их при старте и запоминает версию.

## 5. Приёмы Go, которые встречаются в коде

| Приём | Как выглядит | Где посмотреть |
|---|---|---|
| **Пакет** = папка; имя с заглавной буквы = публичное | `func New()` видна снаружи, `func handler()` — нет | везде |
| **`internal/`** | Импортировать можно только изнутри этого модуля | `internal/*` |
| **Ошибки — это значения** | `if err != nil { return err }` вместо исключений | везде |
| Обёртка ошибок | `fmt.Errorf("...: %w", err)`, проверка `errors.Is(err, sdk.ErrForbidden)` | `plugins/auth/session.go`, `manager.go` |
| **Интерфейс** — набор методов; тип реализует его «молча» | `sdk.Plugin`, `sdk.Host`, `sdk.Identity` | `sdk/sdk.go` |
| Структура + методы | `func (p *Plugin) handleLogin(w, r)`: метод с «получателем» `p` | `plugins/auth/handlers.go` |
| **`http.Handler`** | Всё, у чего есть `ServeHTTP(w, r)`. `http.HandlerFunc` превращает функцию в Handler | `internal/httpx/middleware.go` |
| **Middleware** | Функция `func(next http.Handler) http.Handler`, оборачивает следующий обработчик | `httpx.Chain`, `server.go` |
| Маршруты Go 1.22+ | `"GET /items/{id}"`, затем `r.PathValue("id")` | `plugins/content/api.go` |
| **`context.Context`** | Несёт отмену запроса и «принципала»; `sdk.PrincipalFrom(r.Context())` | `sdk/sdk.go` (внизу) |
| `database/sql` | `QueryRowContext(...).Scan(&a, &b)`, `ExecContext`; `?` — плейсхолдеры (защита от SQL-инъекций) | любой плагин |
| Транзакция | `tx, _ := db.BeginTx(...)`, `defer tx.Rollback()`, `tx.Commit()` | `handleUpdateUser` в auth |
| **`defer`** | Выполнится при выходе из функции (закрыть файл, отпустить мьютекс) | везде |
| **`//go:embed`** | Вшивает файлы в бинарник при компиляции | `content/public.go` (тема), `internal/admin/admin.go` |
| Мьютекс | `sync.Mutex` / `RWMutex` защищает общие данные между горутинами | `plugins/auth/limiter.go` |
| Канал как семафор | `make(chan struct{}, 2)`: не больше двух одновременно | `auth/password.go`, `media/plugin.go` |
| Указатель для «необязательного поля» | `*string` в JSON: `nil` = поле не прислали | `handleUpdateUser` |
| `html/template` | Автоматически экранирует данные; `template.HTML` = «доверяю, не экранировать» | `content/public.go` |
| **Тесты** | Файлы `*_test.go`, функции `TestXxx(t *testing.T)`, `httptest` — фальшивые запросы | все `*_test.go` |

Команды: `go test ./...` (тесты), `go vet ./...` (статический анализ),
`gofmt -w .` (форматирование: в Go стиль не обсуждается, его задаёт инструмент).
`make check` = vet + тесты с детектором гонок (`-race`).

## 6. Где какая защита

| Угроза | Защита | Файл |
|---|---|---|
| Утечка паролей из БД | argon2id (медленный хеш с солью), параметры OWASP | `auth/password.go` |
| Утечка БД → угон сессий | в БД хранится только SHA-256 от токена сессии | `auth/session.go` |
| Кража cookie через JS | `HttpOnly`, `SameSite=Strict`, префикс `__Host-` при HTTPS | `auth/session.go` |
| CSRF | токен в заголовке + проверка `Origin`/`Sec-Fetch-Site` + требование JSON | `auth/session.go`, `sdk/jsonapi.go` |
| Подбор пароля | лимит на сеть (IPv6 по /64) и мягкое замедление на имя пользователя | `auth/limiter.go` |
| Перебор «существует ли пользователь» | одинаковый ответ и одинаковое время | `handleLogin` |
| Удалить последнего админа | атомарная проверка внутри одного SQL `UPDATE`/`DELETE` | `handleUpdateUser` |
| XSS в постах | goldmark без сырого HTML + очистка bluemonday + CSP | `content/render.go` |
| Вредный «файл-картинка» (SVG, HTML) | тип определяется по сигнатуре байт, принимаются только 4 формата | `media/strip.go` |
| GPS в фото | метаданные вырезаются переписыванием контейнера | `media/strip.go` |
| Пиксельная бомба | лимит 50 Мпикс по заголовку, до декодирования | `media/api.go` |
| Выход плагина за свою папку | `os.Root`: ОС не даёт выйти через `..` или symlink | `internal/plugins/files.go` |
| Огромные запросы | лимит тела: 1 МиБ по умолчанию, плагин может объявить больше | `server.go`, `manager.go` |

## 7. Настройки (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `OBLIVION_LISTEN` | `127.0.0.1:8080` | адрес и порт |
| `OBLIVION_DATA_DIR` | `./data` | где лежат БД и файлы плагинов |
| `OBLIVION_SECURE_COOKIE` | `true` | `false` только для локальной разработки без HTTPS |
| `OBLIVION_TRUSTED_PROXIES` | пусто | IP/CIDR reverse-proxy, которому можно верить в `X-Forwarded-For` |
| `OBLIVION_LOG_LEVEL` | `info` | debug / info / warn / error |
| `OBLIVION_LOG_JSON` | `false` | логи в JSON (в контейнере включено) |

## 8. В каком порядке читать код

1. `cmd/oblivion/main.go`: как всё запускается (≈100 строк).
2. `internal/server/server.go`: маршруты и цепочка middleware.
3. `sdk/sdk.go`: «контракт» плагина. Это самое важное для понимания архитектуры.
4. `plugins/content/plugin.go` → `api.go` → `public.go`: самый простой плагин целиком.
5. `plugins/auth/`: сложнее, там вся безопасность входа.
6. `internal/plugins/manager.go` и `host.go`: как ядро грузит плагины и проверяет права.
7. Тесты, например `plugins/content/content_test.go`. Тесты — лучшая документация
   того, *что* код обязан делать.

## 9. Словарь

- **Handler**: функция или объект, который отвечает на HTTP-запрос.
- **Middleware**: обёртка вокруг handler, которая что-то делает до или после него.
- **Principal**: «кто делает запрос» (пользователь и его права).
- **Capability**: право плагина пользоваться частью ядра.
- **Миграция**: SQL-файл, который приводит схему БД к нужной версии.
- **Slug**: часть URL, например `privet-mir` в `/posts/privet-mir`.
- **CSRF**: атака, когда чужой сайт заставляет браузер вошедшего пользователя
  отправить запрос к нам.
- **CSP**: заголовок, который запрещает браузеру выполнять чужие и inline-скрипты.
- **embed**: вшивание файлов в бинарник.
